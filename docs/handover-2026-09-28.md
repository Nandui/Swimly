## 2. What was built (short)

The platform access model, phases 0 to 8, and then the **Work / Me split**. Full
detail is in `docs/platform-access.md` and `docs/staff-app.md`.

- **Access:**
  - A role says *what*, and an assignment says *where or over whom* (site, department, reports).
  - A superadmin tier. Administrators never get HR (restricted) keys.
  - Policy engine in `src/lib/policy`.
  - Multiple roles per person.
  - People core: departments, managers, qualifications.
- **Shared devices:** PIN quick-switch, idle sign-out, and password again for HR.
- **Aquatics:**
  - Medical notes only for reception, swim school managers, and instructors teaching that class.
  - The instructor swimmer lookup.
  - Parent change requests, reviewed under Swimmers → Parent updates.
- **Training:** courses, assigning, trainer sign-off, expiring qualifications, and certificates to check.
- **HR and performance:** separate database; notes and reviews; read log; subject export.
- **Rota:** week view per site; warnings for expired or missing qualifications and double-bookings (never blocks).
- **Design:** Poolside Clear is now the design for the **whole app** (`.turnfin-app` on `<body>`, Plus Jakarta Sans). The Reception Portal's own theme is gone.
- **Work / Me split (your decision yesterday):**
  - **Turnfin Work** has no personal pages any more. `/` opens the role's home, and `/me` is a 404.
  - **Turnfin Me** (`apps/me`) is a separate phone app for each person's own training, required reading, qualifications (and upload), shifts, HR (with a fresh code), details and reminders. It signs in with an email code every time and talks only to `/api/staff/v1`.
  - **Work on work PCs:** Staff → Work devices. The "Work from any device" permission (`work.anywhere`) lets someone sign in elsewhere. It is off until `WORK_DEVICE_REQUIRED=true`.
  - **Reminders:** a daily digest email (cron), and shift-change emails.

## 4. To go live

1. **Decide section 1** (merge to `main`, which applies the migrations).
2. **Make yourself the first superadmin** after the migration:
   `npx tsx scripts/grant-superadmin.ts --email <you> --confirm` (a dry run without `--confirm`).
3. **Turnfin Me:** create a new Vercel project with root directory `apps/me` and
   `NEXT_PUBLIC_STAFF_API_URL=https://<work-host>/api/staff/v1`. Give it its own domain (for example `me.…`).
4. **On Work (Vercel), set:**
   - `STAFF_API_ENABLED=true`
   - `STAFF_AUTH_SECRET` (32+ random characters)
   - `STAFF_API_ALLOWED_ORIGINS` (the Me domain)
   - `STAFF_ME_URL`
   - `CRON_SECRET` (16+ characters)
   - optionally `STAFF_EMAIL_FROM` (it falls back to the parent-app Gmail settings)
5. **Register the centre's PCs** in Staff → Work devices. Give "Work from any
   device" to the roles that need it. Then set `WORK_DEVICE_REQUIRED=true`.
6. **HR:** provision a separate Postgres database and set `HR_DATABASE_URL`. HR
   stays off until then (`docs/hr.md`).
7. **Roles:** create the roles in Roles, then give them out on each person's page.
   - Training lead, Rota planner, Qualifications lead;
   - HR lead, which only a superadmin can create or give out, because it is restricted.
