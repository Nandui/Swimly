## Verification notes
- KEEP: The problem is real, and most of the proposed change matches AUSignIn and AUConfirm. A few details are wrong, though, and one of them contradicts AUSwitch.

Evidence I checked:
- **Sign-in layout.** `auth-frame.tsx:11-19` is one `max-w-sm` (384px) Card with `gap-5 p-6`. The fin is hand-built (`size-[170%]`, line 15) beside a `text-2xl font-bold` 'Turnfin' wordmark (line 17), which renders at 28px/700, so it competes with the H1. Line 23 hard-codes 'for work computers at LeisureWorld', the only LeisureWorld string in `auth-frame.tsx`. Screenshots: `shots/audit2/au01/live/sign_in-1280-light.png` and `sign_in-375-dark.png`, against the two-pane mockup `mock/preview_AUSignIn_html-1280-light.png`.
- **Sign-in form.** At `sign-in-form.tsx:79`, 'No account yet?' is passed as the AuthFrame note, outside the card. `sign-in-form.tsx:86-91` is an info Notice, and `notice.tsx:30` puts its actions under the text. The `tracking-tight` at line 81 does nothing, because the unlayered `.turnfin-app h1` rule at `poolside.css:195` beats Tailwind utilities.
- **Confirm it's you.** `session-forms.tsx:20` uses `gap-5`, so there are 20px between the H1 and the description. Line 115 has a straight apostrophe. Lines 130-131 stack Confirm above a 'Go back' link to '/'. Screenshots: `live/confirm_password-1280-light.png` and `-375-dark.png`, against `mock/preview_AUConfirm_html-1280-light.png`, which shows the fin inside the card and Confirm and Go back side by side in one row.
- **Contrast.** The brand panel passes in both modes: `--pc-on-primary` on `--pc-primary` is 5.82:1 in light and 7.37:1 in dark.
- **Switch page.** `/switch` redirects to `/sign-in` without a shared device, so I could only check it in code against `mock/preview_AUSwitch_html-1280-light.png`.

What is wrong in the proposal:
1. **The radius token doesn't exist.** `--pc-radius-frame` is not defined. `poolside.css:83-86` defines only `--pc-radius-inner`, `--pc-radius-control`, `--pc-radius-card` and `--pc-radius-panel`, and the frame's 36px at line 447 is a literal.
2. **Brand is unused, and its styles break the type rules.** `brand.tsx` is imported nowhere. Its styles at `poolside.css:422-426` draw a 20px/700 wordmark with -0.02em letter-spacing and a 'Docs' module suffix by default. Reusing it brings back type that is off the v2 scale. The shared fin pattern in v2 is `.tf-brand` (`module-shell.tsx:61`, `help-frame.tsx:15`, `instructor-shell.tsx:71`).
3. **The tile is not white in dark mode.** The mockup's tile is `var(--panel)`, which is dark in dark mode, so the token is `--pc-surface`.
4. **The wordmark is larger in the mockup.** AUSignIn draws 'Turnfin' at 28px/600, not at title size (18px).
5. **AUSwitch has no fin in the card.** Only AUConfirm does.
6. **AUSwitch keypad keys are larger, not 44px.** The mockup sets them inline to `min-height: 56px; font-size: 18px`, and it has a ✓ key where the code has an empty `<span/>` (line 97). Live keys render at 44px/14px only because the unlayered rule at `poolside.css:340` silently overrides `min-h-12` and `text-lg`. Moving to the 44px default would fail the brief's own acceptance check against AUSwitch.
7. **Button rows get no hover.** The `.pc-row` hover rule at `poolside.css:529` only targets `a.pc-row`, so a `button.pc-row` would have no hover state. Focus is fine, because the global rule at line 248 covers buttons.
8. **There is no organisation name to read.** `currentSharedDevice` returns only `{id, name, orgId, clubId}` (`shared-device.ts:42-51`).
9. **The action-row gap is smaller than the mockup's.** The mockup uses 12px, not 8px.
- KEEP: Blast radius is small. AuthFrame is used only by sign-in-form.tsx and session-forms.tsx (QuickSwitch, ConfirmPassword). Brand (src/components/workspace/brand.tsx) has no importers today, so reviving it touches no other screen; its .turnfin-docs rules in docs.css don't apply on auth pages. .pc-note (poolside.css:548) and .pc-rows/.pc-row (poolside.css:526-537) are used only by home-view.tsx and home-parts.tsx. The change works with these utilities and doesn't need to restyle them globally. No tests, help guides or scripts depend on the auth copy (grep). The step-up redirect is a page-render redirect (src/lib/policy/session.ts:116,127), which replaces the history entry, so router.back() returns to the page before the restricted one. Contrast passes in both themes: on-primary vs primary is 5.82:1 light and 7.37:1 dark. The screenshot tool signs in through input[type=email], input[type=password] and the first <form>, and the change keeps all three.

As written, though, the change would cause these concrete problems:
1. `var(--pc-radius-frame)` does not exist in poolside.css (grep finds nothing). The brand panel would get square corners.
2. "button.pc-row" as a raw <button> fails `npm run lint`. eslint.config.mjs bans <button> JSX in every src/**/*.tsx outside shadcn (no-restricted-syntax, uiSyntax). Using the shadcn Button with .pc-row also has problems:
   - poolside.css is unlayered and only `a.pc-row` gets hover and focus (lines 529-530). The unlayered .pc-row background beats the ghost variant's layered hover:bg-ui-accent, so the rows show no hover state.
   - Button's base whitespace-nowrap and the browser's centred button text would centre the names or stop them wrapping.
3. Brand defaults module='Docs' and always renders the wordmark span, so the sign-in panel would read "Turnfin Docs". Brand also takes no className. `.turnfin-brand` sets color: var(--pc-ink) on itself (a components layer), so the white text on the blue panel needs a class on Brand's root.
4. A "Go back" Button inside the confirm <form> without type="button" submits the form. With the required password field, it would trigger validation instead of going back.
5. The approved AUSwitch keypad keys are 56px (min-height: 56px ×12 in AUSwitch.html; screenshot shots/audit2/au01-reg/preview_AUSwitch_html-375-light.png). Dropping them to the 44px default cuts the touch PIN pad below both the current 48px and the mockup.
6. AUSwitch shows no fin in the switch card (same screenshot); only AUConfirm does (preview_AUConfirm_html-1280-light.png).
7. The approved mockup is light-only (color-scheme:light). AUSignIn at 768 (preview_AUSignIn_html-768-light.png) shows the brand panel stacked above the form, so "hidden below 768px" means display:none under md (768px), stacked at 768.
8. Once the caption moves into the card, the AuthFrame `note` prop has no caller.
9. The 'at …' footer fallback would need a new organisation query that currentSharedDevice doesn't make (it returns only orgId). Dropping the clause is simpler.

All of these can be fixed by amending the change.
