## Problem
The /hr list panel has no inset and floats its count between two panels. Person and activity panels have 0px between title and list. Rows use the old anatomy (inline tag, body-size lines, ArrowRight, no avatars). Review links use arbitrary-value pill hovers inside 16px cards. The person page puts 'Add note' (primary) first and Withdraw as a ghost on its own 44px line. Add note options render the hint heavier than the name. Share review is a field-less FormDialog. Nothing visible says HR is restricted or that reads are logged. The activity log lists up to 100 bordered cards per column; the Changes panel stretches 4,276px tall beside 'No changes yet.'; entries read 'opened HR record'; columns split 3fr/2fr. The review draft's actions sit left-aligned with no save status. The not-configured notice exposes 'HR_DATABASE_URL … Neon', and Withdraw says 'the person's hub'. There is no back link on records, and the review page uses a ghost ArrowLeft with -ml-3.

1. **`FormDialog` has no destructive option.** It always renders `<LoadingButton type="submit">` (form-dialog.tsx:239). Withdraw needs a reason field, so `ConfirmAction` can't replace it. `FormDialog` needs a new optional prop, which leaves its 66 existing call sites unchanged.

2. **`ChoiceRow` doesn't exist** (grep finds nothing), and lint bans a native `<label>` (eslint.config.mjs:12), so the rows have to use the shadcn `Label`.
   - **Layout breaks if the radio sits outside the label.** module-workspace.css:7 (`.turnfin-module :is(.module-content,[data-slot='dialog-content']) label:not(:has([type='checkbox'],[type='radio'])) {display:block}`, specificity 0,3,1) beats `.turnfin-app .pc-row {display:flex}` (0,2,0).    - **Text gets cramped.** The shadcn `Label` adds `leading-none text-sm font-medium`, and `.pc-row-title` doesn't reset the line height.
   - **Dark mode shows boxes.** `.pc-row` paints `--pc-surface` (#131c2b) inside a dialog painted `--pc-surface-raised` (#182334), so each option shows as a darker box.

3. **Changing the stored `purpose` strings at records.ts:48,74 would damage audit data.**
   - `purpose` is copied as-is into the subject export (`whoReadThisRecord`, export.ts:36).
   - Turnfin Me writes its own value, `'own HR record (Turnfin Me)'` (staff-api/records.ts:247), and export.ts:39 writes `'subject export'`.
   - Older rows keep the old text, so a sentence built from `purpose` would read wrong for history. Build the sentence from the stored `entity` column instead. `hr.test.ts:117` already filters on `entity`.

4. **Two paginated lists would fight over one URL parameter.** `LinkPagination` always uses `?page=` (link-pagination.tsx:22), so two of them would move both lists together. `hrActivity` also has a fixed `LIMIT 100` and no count. The subtitle "The last 100 of each" would then be wrong.

5. **The password-time note can show a bad value.**

   - The app has no time-only formatter. `toLocaleTimeString` on the server would use the server's time zone.

6. **Moving Save and Share to a footer can break saving.** In HRReview the footer sits outside the fields panel. If it also ends up outside the `<form>`, Save draft stops submitting.
