As written, the change has seven regressions or errors, so I'm amending it rather than refuting it:

(a) Moving out of (core) loses that layout's CSS imports (../docs/docs.css, integration.css, ../workspace/module-workspace.css, where .tf-shell, .tf-frame and .tf-rail live). Opened directly, /account would render without the frame. It also loses the (core) metadata, so the tab title falls back to the root template 'Account · Swimly' and the favicon to app-logo.png instead of turnfin.png. It also loses (core)/loading.tsx (PageLoading).

(b) 'A one-link bar that the frame hides' does not exist. ModuleShell (module-shell.tsx:66) shows the bar whenever links.length > 0 and never hides a single link. HomeShell passes no links, so no bar shows at all. The owner-approved ADAccount mockup (preview_ADAccount_html-1280-light.png) shows one filled 'Account' pill with Home current in the rail. HomeShell's pageLabel='Today' is accepted but ignored by ModuleShell, so it is harmless.

(c) describeLevels (levels.ts:175) returns one joined string of labels with no help sentences. Its exact output is asserted in levels.test.ts:103 and written into audit-log summaries (actions/roles.ts:88,131-134; convert-roles.ts:31,46). So 'one row per module with the level's help sentence' needs a structured helper underneath it, without changing that string.

(d) The session holds no levels. The role must be loaded by session.user.roleId, which is the worn role under 'View as' (auth.ts wearPreview). Roles with levels === null need the same fallback as staff/[id]/page.tsx:33.

(e) Alex is a superadmin. His 'Admin: Manage' help says 'every other module except HR', which understates what a superadmin can do.

(f) The current page lists only maya's everywhere-reach permissions (account-1280-light.png shows 5 refunds and docs rows, with no Swim school, Training or Rota), because permissionsOf reads the current site. Level rows fix this but must say where site-reach modules apply.

(g) ADAccount puts the one-line 'Signed in as …, on the Duty manager role.' under the header on the canvas, not inside a panel. 'Inside the first panel' contradicts the mockup the change says to follow.

Smaller items: UserRound becomes an unused import in shell.tsx and core/page.tsx. The PIN-locked Notice (session-forms.tsx:154) still says 'on the shared device'. Help guides-start.ts:54 says 'choose Account', but the menu item is 'Manage account'.
